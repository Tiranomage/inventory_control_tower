# Inventory Control Tower

**Inventory Control Tower** — аналитический проект для розничной сети, который помогает контролировать запасы, дефицит, потерянную выручку и рекомендации по пополнению товаров.

Проект построен как мини-продукт для бизнеса:

```text
продажи → остатки → дефицит → потерянная выручка → риск → рекомендации по заказу → дашборд
```

---

## Бизнес-проблема

Небольшая розничная сеть часто сталкивается с типичными проблемами управления запасами:

- товары заканчиваются, и магазин теряет продажи;
- избыточные запасы замораживают деньги;
- заказы поставщикам делаются вручную и “на глаз”;
- нет единой картины по остаткам, дефицитам и потерям;
- руководитель не видит, сколько выручки теряется из-за отсутствия товара.

Цель проекта — построить аналитическую систему, которая отвечает на вопросы:

1. Что продается и сколько магазин зарабатывает?
2. Где возникает дефицит?
3. Сколько выручки теряется из-за отсутствия товара?
4. Какие товары находятся в зоне риска?
5. Что нужно заказать, в каком количестве и с каким приоритетом?

---

## Что умеет проект

На текущем этапе MVP проект умеет:

- генерировать реалистичные синтетические данные розничной сети;
- хранить данные в SQLite;
- строить SQL-витрины для анализа продаж, остатков и дефицита;
- считать потерянную выручку;
- считать скорость спроса за последние 14 дней;
- оценивать риск дефицита по каждому товару и магазину;
- формировать рекомендации по пополнению запасов;
- выгружать данные в CSV для Yandex DataLens;
- собирать дашборды для контроля запасов и закупок.

## Ключевые метрики

| Метрика | Описание |
|---|---|
| `Revenue` | Фактическая выручка |
| `Lost Revenue` | Упущенная выручка из-за дефицита |
| `Potential Revenue` | Потенциальная выручка при полном удовлетворении спроса |
| `Revenue Capture %` | Доля пойманной выручки от потенциальной |
| `Gross Profit` | Валовая прибыль |
| `Stockout Days` | Количество дней с дефицитом |
| `Stockout Rate` | Доля строк/дней с дефицитом |
| `Days of Supply` | На сколько дней хватит текущего остатка |
| `Avg Daily Demand` | Средний дневной спрос за последние 14 дней |
| `Recommended Order Qty` | Рекомендуемый объем заказа |
| `Estimated Order Cost` | Примерная стоимость рекомендации по заказу |

## Важно про данные

Все данные в проекте синтетические.

Они сгенерированы скриптом:

```text
scripts/generate_data.py
```

Данные имитируют:

- 3 магазина;
- 20 товаров;
- 90 дней продаж;
- сезонность по дням недели;
- дефициты;
- входящие поставки;
- потери продаж из-за отсутствия товара.

Реальные коммерческие данные не используются.

## Установка

Клонируй репозиторий:

```bash
git clone https://github.com/Tiranomage/inventory-control-tower.git
cd inventory-control-tower
```

Создай виртуальное окружение:

```bash
python -m venv .venv
```

Активируй виртуальное окружение.

Для Windows:

```bash
.venv\Scripts\activate
```

Для macOS/Linux:

```bash
source .venv/bin/activate
```

Установи зависимости:

```bash
pip install -r requirements.txt
```

## Использование в Yandex DataLens

После экспорта CSV нужно:

1. Загрузить CSV в DataLens через доступный файловый источник или хранилище.
2. Создать отдельные датасеты:
   - `DL Fact Daily`;
   - `DL Store Daily`;
   - `DL Product KPI`;
   - `DL Stock Risk`;
   - `DL Replenishment`.
3. Проверить типы полей:
   - даты — `Date`;
   - идентификаторы и названия — `String`;
   - количественные показатели — `Integer`;
   - денежные и расчетные показатели — `Float`.
4. Создать вычисляемые показатели:
   - выручка;
   - потерянная выручка;
   - потенциальная выручка;
   - доля пойманной выручки;
   - доля дефицитных строк;
   - средний срок запаса;
   - критичные позиции;
   - стоимость рекомендаций по заказу.
5. Собрать страницы дашборда:
   - Обзор;
   - Риск запасов;
   - Пополнение.

## Примеры бизнес-вопросов, на которые отвечает дашборд

- Сколько выручки теряется из-за дефицита?
- Какие категории теряют больше всего?
- Какие магазины работают хуже по уровню сервиса?
- Какие товары чаще всего отсутствуют в наличии?
- Какие позиции нужно заказать в первую очередь?
- Какой объем закупки нужен для снижения риска дефицита?
- Где заморожены деньги в избыточных запасах?
